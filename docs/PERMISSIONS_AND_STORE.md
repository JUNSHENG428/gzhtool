# 权限说明与上架收窄策略

## 开发态（当前仓库默认）

`manifest.json` 使用较宽的 `host_permissions`：`https://*/*`、`http://*/*`。

**原因简述：**

1. **抓取**：用户可能打开任意公开网页；正文与配图域名无法预先枚举。
2. **用户配置的 AI 接口**：`apiBaseUrl` 指向 OpenAI 兼容网关、自建代理、云厂商等，域名由用户填写。
3. **热点数据源**：`src/shared/hot-topics-sources.js` 中聚合了 RSSHub、公开热榜镜像等，端点可能变更或走备用域名。
4. **公众号接口**：`api.weixin.qq.com`（由 `fetch` 从后台发起，亦需网络权限）。

在本地开发与自用时，宽权限能避免反复改 manifest、反复「加载已解压」。

## 上架态（Chrome Web Store）建议

商店审核通常希望 **权限与功能一一对应、尽量最小化**。可按下面顺序收窄（需实测每个发布流程）：

| 能力 | 建议 `host_permissions` 条目 | 说明 |
|------|------------------------------|------|
| 微信开放平台 | `https://api.weixin.qq.com/*` | 获取 token、上传素材、草稿、发布查询 |
| 用户 AI 接口 | 若只支持单一厂商，可写死该厂商域名；若支持任意 OpenAI 兼容 URL，则仍需较宽 `https://*/*` 或在说明中声明「需访问用户填写的 API 域名」 | 过窄会导致用户无法填自有网关 |
| 热点 RSS / 聚合 | 将 `hot-topics-sources.js` 中实际用到的域名列为显式条目，或改为自有后端代理 | 减少对第三方公开 API 的直连依赖与审核解释成本 |
| 网页抓取 | 若坚持「任意站抓取」，商店侧往往仍需要能访问用户当前页的说明；技术上可保留宽匹配，但须在隐私政策与商店表单中写清用途 | 若只做少数固定站点，可改为仅这些 match patterns |

**不推荐**在未改代码的情况下删除 `http://*/*`：部分用户或内网仍使用 `http` 文章页；若删除，需在文档中说明「仅支持 https 页面」。

## `optional_host_permissions`（可选）

Manifest V3 支持将部分域名列为可选权限，在运行时 `chrome.permissions.request` 再申请。适合「仅在使用热点 / 仅在使用某抓取增强域名时」再要权限。当前仓库未接入 optional 流程，若未来收窄，可逐步迁移。

## 与隐私政策、商店表单的关系

- 宽 `host_permissions` 必须在 **隐私政策** 中说明：访问网络用于用户主动触发的抓取、用户配置的 AI 与公众号接口等。
- **不上传**用户正文到扩展方服务器（本扩展默认无自有后端；若你 fork 加了 analytics，需另述）。
