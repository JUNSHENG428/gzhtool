# 文案问题表：抓取 → AI 改写切片

| 位置 | 现文案 | 问题 | 改写建议 |
|---|---|---|---|
| Workspace 顶部工具条 | 抓取最近浏览页 | 与 popup 的“抓取当前页”不一致。“最近浏览页”对首次用户不够确定，会担心抓错标签页。 | 统一为“抓取当前网页”；如果实际使用最近可抓 tab，提示改为“将抓取你刚打开的网页”。 |
| Popup 主按钮 | 抓取当前页 | 与 Workspace 的“抓取最近浏览页”存在动作名漂移。 | 与 Workspace 统一为“抓取当前网页”。 |
| Capture 视图快捷入口 | 智能识别正文 / 原样抓取整页 / 抓选中文字 | “抓取、识别、原样”动词混用，用户不容易判断三者关系。 | “抓取正文（推荐）”“抓取整页”“抓取选中文字”。 |
| Rewrite 工具条 | AI 新模板 | “AI + 新模板 + PRO”信息密集，按钮会让首次用户误以为当前任务是“改写模板”而不是“改写文章”。 | “生成专属模板”或“AI 生成模板”。 |
| Rewrite 工具条 | 去 AI 味 · 关 | “味”偏口语，“关”缺少动作状态语义。首次用户不一定知道这是二次润色。 | “去 AI 痕迹：关闭”；tooltip 补充“主改写后再做一次润色”。 |
| Rewrite 过程状态 | 主改写完成 ✓ 正在分析 AI 痕迹... | 测试中即使关闭二次润色，也出现“分析 AI 痕迹”，用户可能以为还会继续消耗 AI。 | “主改写完成，正在做本地文本检测...” |
| Rewrite 完成状态 | 当前篇改写完成，已生成标题建议、摘要和可编辑正文。（约 215 字，比目标少约 82%，可让 AI 扩写或换更长档位） | 说明清楚，但没有恢复路径按钮；用户需要自己理解去哪改“长档位”。 | “改写完成，但篇幅偏短。可切换为‘长文’后重新改写，或点击‘扩写当前篇’。” |
| 编辑器操作 | 复制正文 HTML | “HTML”偏技术，不像公众号创作者语言。 | “复制到公众号”或“复制公众号正文”。 |
| 空状态引导 | 先点右上角「抓取最近浏览页」开始 | 和工具条/Popup 名称不统一，且“右上角”会受布局变化影响。 | “点击顶部「抓取当前网页」开始”。 |
